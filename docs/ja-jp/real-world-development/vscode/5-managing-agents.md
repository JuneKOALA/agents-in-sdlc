Copilot をエージェントモードで使うと、コードベースを調査し、変更を提案してファイルを編集し、コマンドを実行するなど、自律的に作業します。VS Code の Copilot Chat では自分のマシンで進む作業を確認でき、各ツール呼び出しやファイル編集がリアルタイムで表示されます。差分をインラインでレビューし、変更を個別に承認または取り消し、エディターを離れずに追加のプロンプトを送って会話の方向を変えたり、作業を拡張したりできます。

この演習では、次の作業を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- セッションの途中でエージェントに指示し、ハイコントラストとともにライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラスト モードを実装しています。作業中に、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加します。新しい会話を最初から始めるのではなく、既存のセッションを方向付けて作業を広げます。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順、調査するファイル、実行するコマンド、提案する編集が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中、チャットをスクロールしてツール操作を確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度試してもらいます。
4. チャット上部の **Files changed** を開くと、このセッションでエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツールの使用 (ターミナル コマンドの実行など) に許可が必要な場合、エージェントは一時停止して **Allow** の確認を表示します。内容を確認し、許可できるコマンドだけを承認してください。

5. エージェントがハイコントラスト モードを実装し終えるまで待ちます。変更内容の概要を示す最終メッセージが表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラスト モードができたので、同じ会話を使ってライトモードの切り替えも追加します。同じチャットを続けることで、エージェントは前の作業、変更したコンポーネント、採用したスタイル、設定した local storage のパターンを引き継ぎます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を確認し、ライトモードの追加案を提示します。
3. 新しい編集が届くたびにレビューし、**Keep** または **Undo** を選択します。
4. エージェントが意図しない方向に進んだ場合 (たとえば、切り替え UI を望まない方法でリファクタリングする場合) は、チャット入力欄の横の **Stop** を選択して停止し、補足のプロンプトを送ります。

> [!TIP]
> 進行中のセッションに指示を送ると、最初からやり直すより速く作業できます。追加プロンプトで変更を依頼できます (「CSS を簡素化し、セレクターを重複させず CSS 変数を使う」)、方向を修正できます (「3つ目の切り替えは追加せず、既存の設定パネルにライトモードを統合する」)、範囲を広げることもできます (「両方の切り替えにキーボード ショートカットも追加する」)。

## 変更されたファイルをレビューする

作業をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. いくつかのファイルを開き、差分を確認します。カスタムエージェントが示したアクセシビリティ パターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定保存) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで進行中のセッションを監視し、方向付けました。ファイル編集を確認して承認または拒否し、コンテキストを保ったまま追加プロンプトを送り、作業を広げました。

この演習では、次の概念を確認しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を承認または拒否する。
- 追加プロンプトでセッションの途中から作業を方向付ける。

[次のレッスン][next-lesson]では、アクセシビリティ作業をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが行った変更をレビューします。
